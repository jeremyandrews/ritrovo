ACCOUNT is the user menu: the kernel renders only `main` and `footer` from config (crates/kernel/src/routes/helpers.rs:249-262), so a config menu named `user` would never reach a template, and the links are written here instead, with the plugin entries that belong to a member. ADMIN is the kernel's Admin link plus every plugin entry under /admin this viewer may open. FOOTER is the `footer` config menu. - Plugin entries arrive as `menus`: the ROOT entries every plugin declared in tap_menu, already filtered to this viewer's permissions (crates/kernel/src/menu/registry.rs:251). The kernel's page.html shows them only when the main menu is empty; here they are split by path into the account and admin menus. Only RITROVO's plugins' entries, and only those with a concrete path: the list also holds the kernel's own plugins' roots (Home, Blog, Media, a blog post at /blog/:slug) and admin routes with a placeholder in them (/admin/content/:id/translate), which are not pages a menu can link to. An entry WITH a parent is in no list a page is given, which is why ritrovo_notify's "Your subscriptions" (parent /user) appears in no menu (FRICTION.md, G-PLUGIN-MENU-ENTRIES-WITH-A-PARENT-RENDER-NOWHERE). - The navigation region is its own block, so the front page can put the tiles placed there inside the page instead of under the header. - A content template that draws its own topic breadcrumb (a conference, a topic listing) marks it `breadcrumb--topics`, and this layout then leaves out the kernel's, which knows the content type and never the topic tree (G-BREADCRUMBS-IGNORE-THE-TOPIC-TREE).
